# Giga Grains content

Public-domain (CC0-1.0) samples for [Giga Grains](https://github.com/sethbc/giga-grains), the
granular synthesizer, and Giga Grains FX, the granular effect: the files their factory presets
load, chosen because they granulate well. Nothing of the plugins' own code is here.

## What is in a release

Each release is a tag (`v1`, `v2`, …; a tag never moves) with one asset,
`giga-grains-content-v<N>.zip`, whose top level is:

```
LICENSE           CC0-1.0, the legal code in full
README.md         this file
PROVENANCE.md     one section per shipped file: its source, license, hashes and how it was made
Samples/
  Strings/        violin, viola, cello and double bass sustains and tremolos, a bowed psaltery
                  and a tremolo zither
  Brass/          horn (open and muted), trumpet (open and harmon mute), trombone, tuba
  Winds/          saxophones, recorders, ocarina, organ, harmonica, didgeridoo
  Mallets/        vibraphone, marimba, bells, chimes, gong, a rubbed wine glass
  Plucked/        harp, kalimba, mbira, psaltery, piano: plucked and struck notes to play
  Textures/       ocean drum, bowed and rolled cymbals, timpani roll, a zither glissando
  Generated/      sweeps, noise beds, a bell and four drones rendered by Giga Grains' gg-render
```

Every sample is FLAC (`flac -8`), at its source's rate and channels, 2 to 20 seconds long, one
note or sound per file, faded in and out over 10 ms and peak-normalized to -1 dBFS. Names are
lowercase ASCII with hyphens; a sharp is spelt `s` (`wine-glass-ds4-rubbed` is D#4). The
strings and brass from VSCO 2: CE are named by their sounding pitch, with middle C as C4 (most of
VSCO 2: CE's own file names call middle C C3, so its `MOHorn_sus_A2` is `horn-a3-sustain` here).

## Where the files come from

- **Downloads** from two libraries by Versilian Studios, each CC0-1.0 and fetched by raw URL at
  one pinned commit, each file checked against its SHA-256:
  - the [Versilian Community Sample Library](https://github.com/sgossner/VCSL) (VCSL; the
    `download` rows of `tools/select.tsv`);
  - [VS Chamber Orchestra: Community Edition](https://github.com/sgossner/VSCO-2-CE) (VSCO 2: CE;
    the `download-vsco` rows), recorded by Sam Gossner and Simon Dalzell, for the orchestral
    strings and the brass.
- **Signals generated** by Giga Grains' own `gg-render`, from the render specs in
  `tools/generated/`; some of them granulate the downloaded files.

Nothing else: no file without a CC0 statement, and no recordings of the authors'. `PROVENANCE.md`
records every file.

## Making a release

1. Edit `tools/select.tsv`: one row per shipped file (the kind, the output path under
   `Samples/`, the library path or the spec, the download's SHA-256, and the trim's start and
   length in seconds). Add rows; never change or remove a released one. Generated rows that read
   downloads come after them.
2. Build `gg-render` in a giga-grains checkout, then run

   ```sh
   GG_RENDER=<giga-grains>/build/dev/tools/gg-render/gg-render \
   GG_RENDER_COMMIT=$(git -C <giga-grains> rev-parse HEAD) \
   tools/make-samples.sh
   ```

   It downloads, checks, trims, normalizes and encodes every new row into `Samples/`, and writes
   `PROVENANCE.md`. A release is a strict superset of the one before: a file `PROVENANCE.md`
   already records is kept, byte for byte with its section, after its SHA-256 is checked, so
   `GG_RENDER` is needed only when a generated row is new. (`--rebuild` remakes every row from
   scratch instead, which a newer gg-render or ffmpeg may make differ from the released bytes.)
   It needs bash, curl, ffmpeg (with ffprobe), flac (with metaflac) and shasum or sha256sum.
3. Commit, push `main`, then zip and release:

   ```sh
   zip -r -X giga-grains-content-v<N>.zip LICENSE README.md PROVENANCE.md Samples -x '*.DS_Store'
   gh release create v<N> giga-grains-content-v<N>.zip --repo sethbc/giga-grains-content \
       --title "Giga Grains content v<N>" --notes-file <notes>
   ```

4. In giga-grains, put the new tag, the asset's URL and its SHA-256 (`shasum -a 256`) in
   `content/pin.txt`.
